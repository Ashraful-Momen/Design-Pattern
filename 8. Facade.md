অবশ্যই 🔥 এবার **Facade Pattern**। এটা Backend Engineer হিসেবে খুব practical—বিশেষ করে যখন একটা operation করতে **অনেকগুলো service/subsystem একসাথে call** করতে হয়।

আগেরগুলোর মতোই আমরা **গল্প → সংজ্ঞা → সমস্যা → pseudo code → raw JS → বাস্তব backend → অন্য pattern-এর সাথে সম্পর্ক → cheat sheet** এই sequence-এ শিখব।

# Design Pattern #7 — Facade Pattern

## 1. আগে গল্প দিয়ে বুঝি

ধরো তুমি একটা **E-commerce application**-এ order place করতে চাও।

একজন customer বলল:

> "আমি এই product-টা order করতে চাই।"

কিন্তু backend-এ order place করা আসলে একটা কাজ না।

অনেকগুলো কাজ করতে হয়:

```text
1. Check Product
2. Check Stock
3. Calculate Price
4. Apply Coupon
5. Process Payment
6. Create Order
7. Update Stock
8. Send Notification
```

অর্থাৎ:

```text
Customer
   ↓
"Place Order"
```

কিন্তু ভিতরে:

```text
Order
 ├── ProductService
 ├── InventoryService
 ├── PricingService
 ├── CouponService
 ├── PaymentService
 ├── OrderService
 └── NotificationService
```

এখন Controller যদি সবগুলোকে নিজে call করে:

```text
Controller
   ↓
ProductService
InventoryService
PricingService
CouponService
PaymentService
OrderService
NotificationService
```

Controller বিশাল হয়ে যাবে। 😵

তাই আমরা একটা **Facade** বানাব।

```text
Controller
    ↓
OrderFacade
    ↓
 ┌──────────────┬──────────────┬──────────────┐
 ↓              ↓              ↓              ↓
Inventory     Pricing       Payment        Order
Service       Service       Service        Service
```

Facade বাইরে থেকে পুরো complex process-কে **একটা simple interface** দেয়।

---

# 2. Facade Pattern-এর সংজ্ঞা

> **Facade Pattern হলো একটি structural design pattern যা complex subsystem-এর ওপর একটি simple, unified interface প্রদান করে।**

সহজ বাংলায়:

> **অনেকগুলো complicated service-এর সামনে একটা simple দরজা বানানো = Facade.**

# 4. Facade ছাড়া Problem

ধরো Controller:

```js
class OrderController {

    async placeOrder(req) {

        const product =
            await productService.find(
                req.productId
            );

        const stock =
            await inventoryService.check(
                product
            );

        const price =
            await pricingService.calculate(
                product
            );

        const discount =
            await couponService.apply(
                req.coupon
            );

        const payment =
            await paymentService.pay(
                price - discount
            );

        const order =
            await orderService.create(
                product,
                payment
            );

        await inventoryService.reduce(
            product
        );

        await notificationService.send(
            order
        );

        return order;
    }
}
```

😵‍💫 Controller এখন business workflow জানে।

এটা ভালো architecture না।

# 6. Pseudo Code

```text
CLASS OrderFacade

    constructor(
        productService,
        inventoryService,
        pricingService,
        couponService,
        paymentService,
        orderService,
        notificationService
    )

        THIS.productService = productService
        THIS.inventoryService = inventoryService
        THIS.pricingService = pricingService
        THIS.couponService = couponService
        THIS.paymentService = paymentService
        THIS.orderService = orderService
        THIS.notificationService = notificationService

    END


    FUNCTION placeOrder(data)

        product =
            productService.find(data.productId)


        inventoryService.check(product)


        price =
            pricingService.calculate(product)


        discount =
            couponService.apply(data.coupon)


        finalPrice =
            price - discount


        payment =
            paymentService.pay(finalPrice)


        order =
            orderService.create(
                product,
                payment
            )


        inventoryService.reduce(product)


        notificationService.send(order)


        RETURN order

    END

END
```

এখানে Facade complex workflow hide করছে।

# 8. এবার Facade বানাই

```js
class OrderFacade {

    constructor(
        productService,
        inventoryService,
        pricingService,
        paymentService,
        orderService,
        notificationService
    ) {

        this.productService =
            productService;

        this.inventoryService =
            inventoryService;

        this.pricingService =
            pricingService;

        this.paymentService =
            paymentService;

        this.orderService =
            orderService;

        this.notificationService =
            notificationService;
    }

    placeOrder(data) {

        const product =
            this.productService
                .find(data.productId);


        this.inventoryService
            .check(product);


        const price =
            this.pricingService
                .calculate(product);


        const payment =
            this.paymentService
                .pay(price);


        const order =
            this.orderService
                .create(
                    product,
                    payment
                );


        this.inventoryService
            .reduce(product);


        this.notificationService
            .send(order);


        return order;
    }
}
```

# 12. খুব গুরুত্বপূর্ণ: Facade Business Logic কি?

এখানে একটা subtle বিষয় আছে।

Facade-এর মধ্যে **workflow/orchestration** থাকতে পারে।

যেমন:

```text
1. Product fetch
2. Stock check
3. Payment
4. Create order
5. Notification
```

কিন্তু domain-এর detailed business rules সব Facade-এ ঢুকিয়ে দেওয়া ঠিক না।

যেমন:

```text
"Premium customer হলে 20% discount"
```

এটা Pricing/Coupon/Domain service-এর responsibility হতে পারে।

Facade-এর responsibility:

> **কোন service কখন call হবে এবং পুরো use-case কীভাবে orchestrate হবে।**

# 13. Facade বনাম Service

এখানে অনেকেই confuse হয়।

### Service

সাধারণত একটি নির্দিষ্ট business capability handle করে।

```text
PaymentService
InventoryService
PricingService
```

### Facade

অনেক subsystem/service-কে coordinate করে।

```text
OrderFacade
    ↓
PaymentService
InventoryService
PricingService
OrderService
```

সহজভাবে:

```text
Service
→ একটা capability

Facade
→ অনেক capability-কে একসাথে ব্যবহার করার simple entry point
```

---

# 14. Facade বনাম Adapter

এটাও খুব গুরুত্বপূর্ণ।

### Adapter

**Interface mismatch solve করে।**

```text
Our Interface
     ↓
 Adapter
     ↓
External Interface
```

Example:

```text
pay()
 ↓
BkashAdapter
 ↓
makePayment()
```

---

### Facade

**Complexity hide করে।**

```text
Simple Interface
      ↓
Facade
      ↓
Many Services
```

Example:

```text
placeOrder()
      ↓
Facade
      ↓
Inventory
Pricing
Payment
Order
Notification
```

### মনে রাখবে:

> **Adapter = Compatibility**

> **Facade = Simplicity**

# 24. Facade-এর একটা Danger ⚠️

Facade-এ সবকিছু ঢুকিয়ে ফেললে সেটা **God Object** হয়ে যেতে পারে।

খারাপ:

```text
OrderFacade
├── 500 lines pricing logic
├── 300 lines payment logic
├── 400 lines inventory logic
├── 300 lines notification logic
└── 500 lines database logic
```

এটা Facade না হয়ে monster class হয়ে যাবে। 😅

ভালো:

```text
Facade
   ↓
Orchestrates

Services
   ↓
Own responsibilities
```

অর্থাৎ Facade-এর কাজ:

> **Coordinate, not own everything.**


# 🧠 Facade Pattern-এর Golden Rule

যখন তুমি দেখবে:

```text
Client
  ↓
Service A
Service B
Service C
Service D
Service E
```

নিজেকে প্রশ্ন করবে:

> **"এই complex subsystem-এর সামনে কি একটা simple entry point দরকার?"**

যদি উত্তর **হ্যাঁ** হয়:

```text
Client
  ↓
Facade
  ↓
A
B
C
D
E
```

# 🚀 এখন পর্যন্ত ৭টা Pattern

| Pattern        | মূল প্রশ্ন                        | Category            |
| -------------- | --------------------------------- | ------------------- |
| **DI**         | Dependency কীভাবে আসবে?           | Principle/Technique |
| **Factory**    | কোন Object তৈরি হবে?              | Creational          |
| **Strategy**   | কোন Behavior চলবে?                | Behavioral          |
| **Repository** | Data Access কোথায় থাকবে?          | Architectural       |
| **Adapter**    | Interface কীভাবে compatible হবে?  | Structural          |
| **Builder**    | Complex Object কীভাবে তৈরি হবে?   | Creational          |
| **Facade**     | Complex subsystem কীভাবে সহজ হবে? | Structural          |

### সবগুলোকে এক লাইনে মনে রাখো:

```text
DI          → dependency inject করো
Factory     → object তৈরি করো
Builder     → object ধাপে ধাপে তৈরি করো
Strategy    → behavior বদলাও
Adapter     → interface মিলাও
Repository  → data access আলাদা করো
Facade      → complex workflow সহজ করো
```

**Facade-এর সবচেয়ে important mental picture:**

```text
             CLIENT
                │
                │ simple call
                ↓
          ┌─────────────┐
          │   FACADE    │
          └──────┬──────┘
                 │
       ┌─────────┼─────────┐
       ↓         ↓         ↓
    Service    Service    Service
       ↓         ↓         ↓
   Repository  Adapter   Strategy
       ↓         ↓         ↓
   Database   External   Algorithm
```

এখানে একটা **Facade পুরো system-এর সব কাজ নিজে করে না**—সে শুধু সঠিক component-গুলোকে সঠিক sequence-এ coordinate করে। এটাই আসল concept। 🔥
