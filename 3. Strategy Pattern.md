অবশ্যই। এবার **Strategy Pattern**-টা এমনভাবে শিখি যেন তুমি শুধু pattern মুখস্থ না করে **কখন, কেন এবং কীভাবে যেকোনো framework-এ implement করতে হয়** সেটা বুঝে যাও।

# Design Pattern #3 — Strategy Pattern

## 1. আগে গল্প দিয়ে বুঝি

ধরো তুমি একটা **E-commerce system** বানাচ্ছ।

Customer order করল। এখন shipping cost বের করতে হবে।

তোমার তিন ধরনের shipping আছে:

```text
Inside Dhaka
Outside Dhaka
Express Delivery
```

প্রতিটির calculation আলাদা।

```text
Inside Dhaka    → 60 টাকা
Outside Dhaka  → 120 টাকা
Express        → 200 টাকা
```

প্রথমে তুমি হয়তো এমন code লিখবে:

```text
FUNCTION calculateShipping(type, order)

    IF type == "inside_dhaka"
        calculate inside dhaka

    ELSE IF type == "outside_dhaka"
        calculate outside dhaka

    ELSE IF type == "express"
        calculate express

END
```

শুরুতে ঠিক আছে।

কিন্তু business বড় হলো।

এখন যোগ হলো:

```text
Same Day
Free Shipping
International
Fragile Product
Heavy Product
```

তখন:

```text
IF
ELSE IF
ELSE IF
ELSE IF
ELSE IF
ELSE IF
...
```

Business logic এক জায়গায় জটলা হয়ে গেল।

**Strategy Pattern এই সমস্যাটা solve করে।**

---

# 2. Strategy Pattern-এর সংজ্ঞা

সহজ ভাষায়:

> **Strategy Pattern হলো এমন একটি design pattern যেখানে একই কাজ করার জন্য একাধিক algorithm/behavior আলাদা আলাদা class-এ রাখা হয় এবং প্রয়োজন অনুযায়ী runtime-এ যেকোনো একটি strategy নির্বাচন করা হয়।**

তিনটা keyword মনে রাখো:

```text
একই কাজ
   ↓
Multiple ways
   ↓
Runtime-এ একটি নির্বাচন
```

যেমন:

```text
Calculate Shipping
       ↓
 ┌─────┼──────────┐
 ↓     ↓          ↓
Dhaka Outside   Express
```

# 3. Strategy-এর মূল Problem

ধরো:

```text
OrderService
```

এর মধ্যে সব calculation ঢুকিয়ে দিলে:

```text
OrderService
│
├── Dhaka calculation
├── Outside Dhaka calculation
├── Express calculation
├── Same Day calculation
└── International calculation
```

`OrderService` বিশাল হয়ে যাবে।

আমরা চাই:

```text
OrderService
      ↓
Shipping Strategy
      ↓
Actual calculation
```

# 4. প্রথমে Strategy ছাড়া Pseudo Code

```text
CLASS ShippingService

    FUNCTION calculate(type, order)

        IF type == "inside_dhaka"

            RETURN 60

        ELSE IF type == "outside_dhaka"

            RETURN 120

        ELSE IF type == "express"

            RETURN 200

        END IF

    END

END
```

Problem:

`ShippingService`-এর মধ্যে প্রতিটি shipping algorithm ঢুকে গেছে।

# 5. Strategy Pattern কী করবে?

আমরা প্রত্যেক algorithm আলাদা করব।

```text

OutsideDhakaStrategy
ExpressStrategy
```

প্রতিটা নিজের calculation করবে।

```text

       ↓
calculate()

OutsideDhakaStrategy
       ↓
calculate()

ExpressStrategy
       ↓
calculate()
```

তারপর একটি common concept থাকবে:

```text
ShippingStrategy
       ↑
 ┌─────┼──────────────┐
 ↓     ↓              ↓
Dhaka Outside       Express
```

# 6. Pseudo Code

প্রথমে strategy:

```text
CLASS InsideDhakaStrategy

    FUNCTION calculate(order)

        RETURN 60

    END

END
```

```text
CLASS OutsideDhakaStrategy

    FUNCTION calculate(order)

        RETURN 120

    END

END
```

```text
CLASS ExpressStrategy

    FUNCTION calculate(order)

        RETURN 200

    END

END
```

এখন মূল service:

```text
CLASS ShippingService

    FUNCTION constructor(strategy)

        THIS.strategy = strategy

    END


    FUNCTION calculate(order)

        RETURN THIS.strategy.calculate(order)

    END

END
```

এখানেই Strategy Pattern-এর core।

# 7. Strategy কীভাবে বদলাব?

```text
dhakaStrategy =
    NEW InsideDhakaStrategy()

shippingService =
    NEW ShippingService(dhakaStrategy)
```

এখন:

```text
shippingService.calculate(order)
```

Inside Dhaka calculation হবে।

কিন্তু:

```text
expressStrategy =
    NEW ExpressStrategy()

shippingService =
    NEW ShippingService(expressStrategy)
```

এখন একই `ShippingService` Express calculation করবে।

**Service পরিবর্তন করতে হলো না।**

# 10. Context Class

Strategy Pattern-এ যে class strategy ব্যবহার করে তাকে সাধারণত **Context** বলা হয়।

```js
class ShippingService {

    constructor(strategy) {
        this.strategy = strategy;
    }

    calculate(order) {
        return this.strategy.calculate(order);
    }
}
```

এখানে:

```text
ShippingService = Context

strategy = Strategy
```

# 16. Factory + Strategy একসাথে

এখানে আগের **Factory Pattern**-ও কাজে লাগতে পারে।

```text

```

```text

          ↓
       "bkash"
          ↓
BkashPaymentStrategy
```

তারপর DI:

```text
BkashPaymentStrategy
          ↓
      inject into
          ↓
   PaymentService
```

পুরো flow:

```text
Request
   ↓
Factory
   ↓
Strategy নির্বাচন
   ↓
PaymentService
   ↓
Strategy.pay()
```

এটা real backend architecture-এ খুব common ধরনের composition।

# 20. Strategy কখন ব্যবহার করবে না?

শুধু ২টা simple condition-এর জন্য Strategy বানিয়ে ১০টা class বানানোর দরকার নেই।

যেমন:

```js
if (age >= 18) {
    return "adult";
}

return "minor";
```

এর জন্য Strategy Pattern **overengineering**।

Strategy ব্যবহার করো যখন:

```text
Algorithms are:
    ↓
multiple
+
meaningfully different
+
likely to change/extend
```

# 21. Strategy-এর বড় সুবিধা

### 1. Open/Closed Principle

নতুন strategy যোগ করতে পারো:

```text
NewStrategy
```

কিন্তু Context পরিবর্তন করতে হয় না।

---

### 2. Loose Coupling

```text
Context
  X
specific algorithm
```

বরং:

```text
Context
  ↓
Strategy
```

---

### 3. Testability

একটা fake strategy দিতে পারো:

```js
const fakeStrategy = {

    calculate(order) {
        return 0;
    }
};

const service =
    new ShippingService(fakeStrategy);
```

Real algorithm ছাড়াই test করা যায়।

---

### 4. Maintainability

প্রতিটি algorithm আলাদা file/class:

```text
strategies/
├── BkashPaymentStrategy.js
├── NagadPaymentStrategy.js
├── CardPaymentStrategy.js
└── RocketPaymentStrategy.js
```

Business logic clean থাকে।

---

# 22. একটা গুরুত্বপূর্ণ Advanced Concept

Strategy সবসময় class হতে হবে এমন না।

JavaScript-এ function দিয়েও Strategy করা যায়।

```js
const insideDhaka =
    (order) => 60;

const outsideDhaka =
    (order) => 120;

const express =
    (order) => 200;
```

তারপর:

```js
function calculateShipping(
    order,
    strategy
) {
    return strategy(order);
}
```

ব্যবহার:

```js
calculateShipping(
    order,
    express
);
```

এটাও Strategy-এর **core idea**।

কারণ JavaScript-এ function first-class object।

তবে OOP/framework architecture শেখার জন্য class-based version আগে বুঝে রাখা ভালো।

# 23. Strategy-এর Mental Model

যখন কোনো problem দেখবে, নিজেকে জিজ্ঞেস করবে:

```text
এই কাজটা কি বিভিন্নভাবে করা যায়?
             ↓
            YES
             ↓
এই algorithms কি আলাদা করে রাখা যায়?
             ↓
            YES
             ↓
Runtime-এ একটি নির্বাচন করতে হবে?
             ↓
            YES
             ↓
       STRATEGY
```

# 24. DI + Factory + Strategy — তিনটা একসাথে

এখন তোমার আগের দুই pattern-এর সাথে connect করো।

```text
                 Request
                    ↓
              PaymentController
                    ↓
              PaymentService
                    ↑
                    │ DI
                    │
            PaymentStrategy
                    ↑
                    │
              PaymentFactory
                    ↑
                    │
              "bkash"
```

Factory:

```text
কোন Strategy object?
```

Strategy:

```text
কীভাবে payment করবে?
```

DI:

```text
Strategy কীভাবে PaymentService-এ আসবে?
```

### এক লাইনে:

```text
Factory → WHAT OBJECT?
Strategy → WHAT BEHAVIOR?
DI → HOW DEPENDENCY ARRIVES?
```

এই তিনটা distinction মাথায় খুব ভালোভাবে বসিয়ে রাখো।

# 🧠 Final Cheat Sheet

```text
STRATEGY PATTERN
│
├── Category
│     └── Behavioral
│
├── Problem
│     └── Multiple algorithms/behaviors
│
├── Solution
│     └── Put each algorithm in separate strategy
│
├── Context
│     └── Uses the selected strategy
│
├── Strategy
│     └── Defines behavior/algorithm
│
├── Benefits
│     ├── Loose Coupling
│     ├── Easy Extension
│     ├── Testability
│     └── Avoid giant IF/ELSE
│
└── Common Examples
      ├── Payment
      ├── Shipping
      ├── Pricing
      ├── Authentication
      ├── Sorting
      ├── File Processing
      └── AI Providers
```

### তিনটা Pattern একসাথে মনে রাখো:

```text
┌──────────┬─────────────────────────────┐
│ DI       │ Dependency কীভাবে আসবে?    │
├──────────┼─────────────────────────────┤
│ Factory  │ কোন Object তৈরি হবে?       │
├──────────┼─────────────────────────────┤
│ Strategy │ কোন Behavior চলবে?         │
└──────────┴─────────────────────────────┘
```

**Strategy-এর এক লাইনের definition:**

> **একই কাজের একাধিক algorithm/behavior-কে আলাদা করে রাখি এবং প্রয়োজন অনুযায়ী যেকোনো একটি ব্যবহার করি।**

পরের sequence অনুযায়ী **#4 Repository Pattern**-এ গেলে এবার আমরা সরাসরি **Controller → Service → Repository → Database** দিয়ে একটা complete backend flow বানাব। সেখানে DI + Factory + Strategy-এর সাথে Repository কীভাবে বসে, সেটাও পরিষ্কার হবে।
