অবশ্যই 🔥 এবার **Builder Pattern**। এটা আগেরগুলোর থেকে একটু আলাদা—এখানে মূল focus হলো **complex object ধাপে ধাপে তৈরি করা**, বিশেষ করে যখন object-এর অনেক optional configuration থাকে।

# Design Pattern #6 — Builder Pattern

## 1. আগে গল্প দিয়ে বুঝি

ধরো তুমি একটা **E-commerce Order** বানাচ্ছ।

একটা Order-এর মধ্যে থাকতে পারে:

```text
Customer
Product
Quantity
Address
Coupon
Discount
Shipping
Payment Method
Notes
```

কিন্তু সব order-এ সব information লাগবে না।

একটা সাধারণ order:

```text
Customer
Product
Quantity
```

আর একটা premium order:

```text
Customer
Product
Quantity
Address
Coupon
Discount
Express Shipping
Card Payment
Notes
```

এখন তুমি যদি constructor দিয়ে সবকিছু বানাতে যাও:

```text id="s5f7c2"
new Order(
    customer,
    product,
    quantity,
    address,
    coupon,
    discount,
    shipping,
    payment,
    notes
)
```

সমস্যা শুরু। 😵

কোন parameter কোনটা?

আর optional parameter অনেক হলে code খুব hard to read হয়।

**Builder Pattern এই problem solve করে।**

---

# 2. Builder Pattern-এর সংজ্ঞা

সহজ ভাষায়:

> **Builder Pattern হলো একটি creational design pattern যেখানে complex object-কে একবারে তৈরি না করে ধাপে ধাপে বিভিন্ন অংশ configure করে শেষে final object তৈরি করা হয়।**

Mental model:

```text id="m8f3v1"
Builder
   ↓
set Customer
   ↓
set Product
   ↓
set Address
   ↓
set Coupon
   ↓
set Shipping
   ↓
build()
   ↓
Final Object
```

# 6. প্রথমে Pseudo Code

আমাদের Product:

```text id="n3w6t9"
CLASS User

    name
    email
    phone
    address
    age

END
```

এখন সব field একসাথে দিতে চাই না।

Builder:

```text id="a8q5m2"
CLASS UserBuilder

    FUNCTION setName(name)

        THIS.name = name

        RETURN THIS

    END


    FUNCTION setEmail(email)

        THIS.email = email

        RETURN THIS

    END


    FUNCTION setPhone(phone)

        THIS.phone = phone

        RETURN THIS

    END


    FUNCTION setAddress(address)

        THIS.address = address

        RETURN THIS

    END


    FUNCTION build()

        RETURN NEW User(
            THIS.name,
            THIS.email,
            THIS.phone,
            THIS.address
        )

    END

END
```

---

# 7. এখানে `RETURN THIS` কেন?

এটা Builder Pattern-এর খুব গুরুত্বপূর্ণ অংশ।

যেমন:

```text id="g8p4v1"
builder.setName()
```

returns:

```text id="j2k6m9"
builder
```

তাই আমরা লিখতে পারি:

```text id="p5x9r3"
builder
    .setName()
    .setEmail()
    .setPhone()
    .build()
```

এটাকে বলা হয় **Method Chaining**।

# 15. Builder + Validation

Builder-এর একটা বড় সুবিধা হলো `build()` করার আগে validation করতে পারো।

```js id="p3r7k5"
class UserBuilder {

    constructor() {
        this.data = {};
    }

    setName(name) {

        this.data.name = name;

        return this;
    }

    setEmail(email) {

        this.data.email = email;

        return this;
    }

    build() {

        if (!this.data.name) {
            throw new Error(
                "Name is required"
            );
        }

        if (!this.data.email) {
            throw new Error(
                "Email is required"
            );
        }

        return new User(this.data);
    }
}
```

এখন:

```text id="w8m4q1"
set fields
   ↓
validate
   ↓
build()
   ↓
valid object
```

# 17. এবার একটু Realistic Order Example

```js id="u4n8k2"
class Order {

    constructor(data) {

        this.customer = data.customer;
        this.items = data.items;
        this.address = data.address;
        this.coupon = data.coupon;
        this.shipping = data.shipping;
        this.payment = data.payment;
    }
}
```

Builder:

```js id="x6m3q9"
class OrderBuilder {

    constructor() {

        this.data = {
            items: []
        };
    }

    setCustomer(customer) {

        this.data.customer = customer;

        return this;
    }

    addItem(item) {

        this.data.items.push(item);

        return this;
    }

    setAddress(address) {

        this.data.address = address;

        return this;
    }

    setCoupon(coupon) {

        this.data.coupon = coupon;

        return this;
    }

    setShipping(shipping) {

        this.data.shipping = shipping;

        return this;
    }

    setPayment(payment) {

        this.data.payment = payment;

        return this;
    }

    build() {

        if (!this.data.customer) {
            throw new Error(
                "Customer required"
            );
        }

        if (this.data.items.length === 0) {
            throw new Error(
                "Order must have items"
            );
        }

        return new Order(this.data);
    }
}
```

# 19. Builder + Factory

এখন interesting part।

Factory বলেছিল:

> **কোন object তৈরি করব?**

Builder বলছে:

> **Object-টা ধাপে ধাপে কীভাবে configure করব?**

তাই দুটো একসাথে হতে পারে।

```text id="n3q7k1"
Factory
   ↓
কোন Builder?
   ↓
Builder
   ↓
configuration
   ↓
build()
   ↓
Object
```

যেমন:

```text id="a8m2p5"
ReportFactory
      ↓
PDFReportBuilder
      ↓
setTitle()
setData()
setHeader()
      ↓
build()
      ↓
PDF Report
```

# 21. Builder + DI

Builder নিজেও dependency নিতে পারে।

যেমন:

```js id="h4q8m6"
class ReportBuilder {

    constructor(formatter) {

        this.formatter = formatter;
    }

    setData(data) {

        this.data = data;

        return this;
    }

    build() {

        return this.formatter
            .format(this.data);
    }
}
```

```js id="k6m3p9"

    new ReportBuilder(formatter);
```

# 27. Builder-এর Advanced Idea — Immutable Object

Builder-এর আরেকটা গুরুত্বপূর্ণ use case হলো final object-কে immutable রাখা।

Concept:

```text id="x8m3q5"
Builder
  ↓
Mutable configuration
  ↓
build()
  ↓
Immutable Final Object
```

মানে Builder-এর configuration পরিবর্তন করা যাবে, কিন্তু final object তৈরি হওয়ার পর সেটাকে সহজে modify করা হবে না।

এটা Java ecosystem-এ খুব common design style।

```text
┌─────────────┬──────────────────────────────────┐
│ DI          │ Dependency কীভাবে আসবে?         │
├─────────────┼──────────────────────────────────┤
│ Factory     │ কোন Object তৈরি হবে?            │
├─────────────┼──────────────────────────────────┤
│ Strategy    │ কোন Behavior/Algorithm চলবে?    │
├─────────────┼──────────────────────────────────┤
│ Repository  │ Data Access কোথায় থাকবে?        │
├─────────────┼──────────────────────────────────┤
│ Adapter     │ Interface কীভাবে মিলবে?         │
├─────────────┼──────────────────────────────────┤
│ Builder     │ Complex Object কীভাবে তৈরি হবে?│
└─────────────┴──────────────────────────────────┘
```

### Builder-এর এক লাইনের definition:

> **Builder = Complex object-কে একবারে constructor দিয়ে না বানিয়ে, ধাপে ধাপে configure করে শেষে `build()` দিয়ে তৈরি করা।**

আর একটা code দেখলেই Builder চিনবে:

```js
const order = new OrderBuilder()
    .setCustomer(customer)
    .addItem(product)
    .setAddress(address)
    .setShipping("express")
    .setPayment("bkash")
    .build();
```

এখানে **`set... → set... → set... → build()`** দেখলেই তোমার মাথায় **Builder Pattern** আসা উচিত। 🔥
