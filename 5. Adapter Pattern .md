অবশ্যই 😍 এবার **Adapter Pattern**। এটা Backend Engineer হিসেবে খুব গুরুত্বপূর্ণ—বিশেষ করে **third-party API, legacy system, payment gateway, external service, database driver** integrate করার সময়।

আগের patternগুলোর মতোই একদম **framework-independent**ভাবে শিখব।

# Design Pattern #5 — Adapter Pattern

## 1. আগে গল্প দিয়ে বুঝি

ধরো তোমার application-এর একটা rule আছে:

```text
আমাদের system payment দিতে চাইলে
সব payment provider-এর method হবে:

pay(amount)
```

তাই তোমার code ধরে নিয়েছে:

```text
Payment
   ↓
pay(amount)
```

এখন তুমি একটা third-party payment gateway integrate করলে।

তাদের API:

```text
bKash API
   ↓
makePayment(amount)
```

অর্থাৎ তোমার application চায়:

```text
pay(amount)
```

কিন্তু external API দেয়:

```text
makePayment(amount)
```

দুইজনের interface মিলছে না।

তখন কী করবে?

তুমি পুরো application বদলাবে?

**না।**

মাঝখানে একটা **Adapter** বসাবে।

```text
Your Application
      ↓
   pay(amount)
      ↓
   Adapter
      ↓
makePayment(amount)
      ↓
 bKash API
```

এটাই Adapter Pattern-এর মূল idea।

---

# 2. Adapter Pattern-এর সংজ্ঞা

সহজ ভাষায়:

> **Adapter Pattern হলো এমন একটি structural design pattern যা incompatible interface-কে এমন একটি interface-এ রূপান্তর করে যেটা client সহজে ব্যবহার করতে পারে।**

আরও সহজ করে:

> **দুইটা জিনিস সরাসরি কথা বলতে না পারলে মাঝখানে Translator বসানো = Adapter.**


এ convert করছে।

# 8. Pseudo Code

Adapter:

```text id="t2f9u5"
CLASS BkashAdapter

    constructor(bkashAPI)

        THIS.bkashAPI = bkashAPI

    END


    FUNCTION pay(amount)

        RETURN THIS.bkashAPI
                   .makePayment(amount)

    END

END
```

এখন Application:

```text id="4r4k2m"
bkashAPI =
    NEW BkashAPI()

payment =
    NEW BkashAdapter(bkashAPI)

payment.pay(1000)
```

Application ভাবছে:

```text id="h3n0c4"
payment.pay()
```

কিন্তু Adapter internally করছে:

```text id="c6b3u9"
bkashAPI.makePayment()
```

# 9. এবার Raw JavaScript

### Our expected interface

```js id="v8j1fq"
class PaymentService {

    pay(payment, amount) {
        return payment.pay(amount);
    }
}
```

আমাদের নিজের implementation:

```js id="6l3q6p"
class CardPayment {

        console.log(
            `Card payment: ${amount}`
        );
    }
}
```

এখন external API:

```js id="k9j5y0"
class BkashAPI {

    makePayment(amount) {

        console.log(
            `Calling Bkash API: ${amount}`
        );

        return {
            success: true
        };
    }
}
```

Problem:

```text id="f9g7oc"
PaymentService
       ↓
expects pay()
       ↓
BkashAPI
       ↓
only has makePayment()
```

---

# 10. Adapter তৈরি করি

```js id="0o6y8a"
class BkashAdapter {

    constructor(bkashAPI) {
        this.bkashAPI = bkashAPI;
    }

    pay(amount) {

        return this.bkashAPI
            .makePayment(amount);
    }
}
```

এখন:

```js id="v6k7d4"
const bkashAPI =
    new BkashAPI();

const bkashPayment =
    new BkashAdapter(bkashAPI);

const paymentService =
    new PaymentService();

paymentService.pay(
    bkashPayment,
    1000
);
```

Output:

```text id="d5j8q0"
Calling Bkash API: 1000
```

# 17. একটা গুরুত্বপূর্ণ পার্থক্য: Adapter vs Strategy

এগুলো অনেক সময় নতুনদের confuse করে।

### Strategy

একই কাজের **multiple algorithms/behaviors**।

```text id="x8c3m1"
Payment
 ├── Bkash Strategy
 ├── Card Strategy
 └── Nagad Strategy
```

প্রশ্ন:

> **কোন behavior ব্যবহার করব?**

---

### Adapter

একটা existing/external implementation-এর interface **আমাদের interface-এর সাথে compatible করা**।

```text id="r2q8v6"
Our Interface
     ↓
 Adapter
     ↓
Third-party API
```

প্রশ্ন:

> **এই incompatible interface-কে কীভাবে আমাদের interface-এর মতো ব্যবহার করব?**

---

# 18. Adapter vs Factory

### Factory:

```text id="x3d7q1"
কোন object বানাব?
```

### Adapter:

```text id="b9m4t2"
Object-এর interface কীভাবে compatible করব?
```

# 19. Adapter vs Repository

এটাও গুরুত্বপূর্ণ।

Repository:

```text id="p8k3w5"
Business Layer
      ↓
Repository
      ↓
Database
```

Repository-এর উদ্দেশ্য:

> Data access abstraction.

Adapter:

```text id="m6r1z9"
Application
     ↓
Adapter
     ↓
External/Existing System
```

Adapter-এর উদ্দেশ্য:

> Interface compatibility.

Repository আর Adapter একই জিনিস নয়।

# 21. Third-party API Response-ও Adapter করা যায়

ধরো external API দেয়:

```json
{
    "customer_name": "Rahim",
    "customer_phone": "01700000000"
}
```

কিন্তু তোমার application চায়:

```json
{
    "name": "Rahim",
    "phone": "01700000000"
}
```

Adapter:

```js id="6c2x8v"
class CustomerAdapter {

    constructor(api) {
        this.api = api;
    }

    async getCustomer(id) {

        const response =
            await this.api.getCustomer(id);

        return {
            name: response.customer_name,
            phone: response.customer_phone
        };
    }
}
```

এখানে শুধু method না—**data format-ও adapt করা হচ্ছে।**

```text
bKash
Nagad
SMS Gateway

AI API
```

### ② Legacy System

```text

```

### ③ Different interfaces

```text

External:
makePayment()
```

### ④ Different data formats

```text

Internal:
name
```

### ⑤ Vendor change

```text

     ↓
```

```text

     ↓

     ↓
```

# 27. পাঁচটা Pattern-এর পার্থক্য

| Pattern        | মূল প্রশ্ন                                    |
| -------------- | --------------------------------------------- |
| **DI**         | Dependency কীভাবে আসবে?                       |
| **Factory**    | কোন object তৈরি হবে?                          |
| **Strategy**   | কোন behavior/algorithm চলবে?                  |
| **Repository** | Data access কোথায় থাকবে?                      |
| **Adapter**    | Incompatible interface কীভাবে compatible হবে? |

এগুলো **একই ধরনের pattern নয়**:

```text id="j2q6m8"
DI
→ Technique / Principle

Factory
→ Creational

Strategy
→ Behavioral

Repository
→ Data-access / Architectural

Adapter
→ Structural
```

# 🧠 Adapter Pattern — Final Cheat Sheet

```text id="q7m3x9"
ADAPTER PATTERN
│
├── Category
│     └── Structural
│
├── Problem
│     └── Two interfaces are incompatible
│
├── Solution
│     └── Add Adapter between them
│
├── Client expects
│     └── pay()
│
├── Adapter provides
│     └── pay()
│
├── Adapter internally calls
│     └── makePayment()
│
├── Common Uses
│     ├── Third-party APIs
│     ├── Payment Gateways
│     ├── Legacy Systems
│     ├── External Services
│     ├── API Response Mapping
│     └── Vendor Integration
│
└── Main Benefit
      └── Loose Coupling
```

### এক লাইনে মনে রাখো:

> **Adapter = “আমার application যে interface বোঝে, external system-কে সেই interface-এ কথা বলানোর Translator।”**

আর সবচেয়ে important diagram:

```text id="n2f6r8"
              YOUR APPLICATION
                     │
                     │ pay()
                     ↓
                  ADAPTER
                     │
                     │ makePayment()
                     ↓
               THIRD-PARTY API
```

**এই patternটা ভালোভাবে আয়ত্ত করলে Laravel-এর Service/Integration layer, Spring Boot-এর external client integration, Next.js/Node-এর third-party API wrapper—সব জায়গায় একই underlying concept চিনতে পারবে।**
